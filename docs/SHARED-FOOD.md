# 美波飯の共通元データ連携

## 確認した正本・出典

元アプリは [minamigoen/MinamiGo](https://github.com/minamigoen/MinamiGo)（美波飯マップ）。コードの `API_URL` と `webApp.gs` が、既存の非公開Google Sheets `eat` タブの12列を匿名公開JSONとして提供しています。repoのSheet IDは伏せられており、アプリ本体にCSV/JSONの正本を持つ方式ではありません。

[元アプリが利用する公開API](https://script.google.com/macros/s/AKfycbwUu-Xl9mpPWdnZGacuebLcC8mHy-eZv86EnQqxaUG9djOkA7lf2fByRYmj8ZDC4E_2/exec) は2026-10-13の実取得で37件。公開アプリと同じoriginからcredentialsを送らないブラウザ取得もHTTP200/37件で確認しました。既存接続で元編集用Sheetの `eat`（37件）とNO/名称・公開項目の対応を照合しています。元アプリと元Sheetを変更・公開・権限拡大していません。非公開Sheet ID/URLはこのrepoに保存しません。

元JSONの項目は `no,name,address,lat,lng,tel,comment,hours,closed,url,sns,image`。新アプリで使用するのは基本情報の10項目（comment/imageを除く）のみで、URL/電話/座標/重複IDを検証します。その他の非公開/未知列、備考、画像、資格情報を取り込みません。HTTPSではないURLや認証情報を含むURLは安全なリンクとして採用せず、勝手にHTTPSへ書き換えもしません。

## 単一正本と補足情報

飲食店の名称・住所・電話・営業時間・休日・サイト/SNS・掲載座標は、元美波飯と同じ公開APIを正本として読みます。街歩き側で基本情報を二重編集しません。更新は元の `eat` を編集する既存方式です。元の非公開Sheetを編集できる権限を持つ担当者が操作し、この作業では変更していません。

街歩き側の非公開テストSheetは、伝承7件と、飲食店の分類・紹介文・補足リンク・権利確認済み写真・関連案内確認日の編集元です。`data/local-content.json` は伝承7件＋6店の補足項目だけを持ち、飲食店の名称/住所/電話/営業時間をコピーした第二正本にはしません。`data/spots.json` は7＋37＋宿泊26＝70件の**派生した公開時の正常スナップショット**で、直接編集する正本ではありません。

管理Sheetの飲食店行に以前の基本情報が残っていても、共通連携では採用しません。基本情報は元 `eat`、分類/リンク/写真は街歩き側と役割を分けます。publicApprovedは街歩き補足の公開承認で、元APIから既に公開されている店舗の掲載可否は元データ側で管理します。

既存6店は置き換えて同一IDで扱い、6件を別途足さないので重複しません。他の31件は `minamimeshi-<元NO>`。数字NOは10桁に揃え、表記の空白・全半角も照合します。既知店舗のNO/名称が対応表と矛盾した場合は勝手にお気に入りを別店舗へ移さず、直近正常データを保持して対応表レビューを必要とします。

元APIは業態を公開しないため、新しい31件の料理分類は「種類未確認」とし、名前だけで料理や営業状況を捏造しません。掲載座標は元データの値で、入口/現況/経路は未検証と表示します。記事更新日/営業中の判定はAPIにありません。

## 更新条件

- **実行時**: 起動/再読み込みで元公開APIを読みます。正常取得した元情報は端末で10分再利用し、元 `eat` の変更は次の取得に反映。使い方の「掲載情報を再読み込み」は10分を待たず明示取得します。開きっぱなしの画面を常時ポーリングする方式ではありません。
- **失敗/オフライン**: 直近正常の元情報＋現在の街歩き補足を合成して表示。初回で端末保存がなければ70件の公開時スナップショットを表示します。空配列、重複NO、異常スキーマ、座標異常、通信/CORS失敗では正常保存を上書きしません。
- **公開時の再生成**: `npm run sync:food` をネットワークから元APIへ到達できる環境で実行し、検証済み70件を生成してcommit/公開します。既に取得した公開JSONなら `node scripts/sync-food.mjs /tmp/public-food-facts.json`。不正データは終了コード1、前回正常スナップショットを保持します。
- **街歩き補足更新**: 既存コネクタで非公開テストSheetの承認済み項目を読み、既存importコマンドを実行すると `local-content.json` を更新します。基本情報は共通正本を優先。その後snapshot再生成・検証・SW version更新・テスト公開を行います。

公開APIが匿名/CORS対応で利用可能、既存NOとスキーマが保たれることが実行時連携の条件です。元GASの公開URLや返却構造を変更した場合は設定/アダプタを更新します。旧repoの例では毎回Sheetを読み、CacheServiceへputするのみでgetによる応答cacheは実装されていません。無料GASの利用上限/可用性は保証しません。新しいサーバー・APIキー・OAuth・GitHub書込権限や定期書込automationは追加していません。

## 写真

公開APIにはimage値が37件ありますが、利用条件/クレジットは提供されません。既存元表に画像管理欄があっても、今回、転載許諾済みと確認できる情報は得られていません。元imageは一切使用/保存/再掲せず、街歩き側で権利確認しphotoApprovedした写真だけを補足として使います。元アプリの既存写真をこちらで許諾済みと断定しません。

## 検証

公開API37件、匿名ブラウザCORS、6店ID対応、70件合成、sourceの追加/削除・変更、未知/私的列と画像除外、URL/資格情報安全性、重複/不正スキーマの停止、10分cacheと明示再読込、失敗とオフラインで直近正常の保持を検証します。元repo/mainと元Sheetの読み取り専用を維持します。

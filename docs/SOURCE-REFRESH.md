## 出典・利用条件・再取込

個別確認済み補完は `data/web-supplements.json`、OSM由来の座標データは `data/osm-locations.json` に分離する。後者は © OpenStreetMap contributors、[ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/) による公開データ。施設詳細・フッター・空中写真の地図帰属に表示し、対応データも公開する。他の写真・文章・アプリ全体へ同じライセンスを付けるものではない。

`npm run sync:web` は名称・ID・根拠・許可フィールドを検証し、許諾写真・施設同一性を変更しない。`sync:life`、`sync:sightseeing`、`sync:local` でも補完を保持し、元のSheetを編集せず、公開APIの再取得でも補完が消えないことを試験する。新しい原典差分が手動補完と衝突するときは再確認を必要とする。

## 定期処理

既存 `town-source-review.yml` に毎日21:17 UTC（翌06:17日本時間）のscheduleと手動実行を設定。GitHubの混雑等で実行時刻が遅れる場合がある。既存の `contents: read` を維持し、権限・認証・有料サービスを追加しない。

`python scripts/refresh-sources.py` が町観光HP・観光RSS最新20件・当月ICSを取得し、差分候補と実行サマリーを `staging/` に保存する。Actions artifactの `municipal-source-candidates` に14日保存し、job summaryにも成否を表示する。原典の空・構造変更・件数急減・不正URL・取得失敗はblockedにし、公開JSONの処理前後ハッシュ一致を確認する。失敗した原典があっても他の原典の結果を保存する。

RSSの日付は記事公開日であり開催日に転用しない。最新20件から消えた記事を削除しない。ICSはUID重複、終日DTEND、例外・中止、対象年を検証し、町カレンダーにないイベントも既存記事根拠を保持する。年・名称・写真・座標・手動保護値の自動上書きはしない。

**自動公開は保留**：現在のworkflowは読取権限のみ。無人でmainや公開Sheetを書き換えるには書込権限の追加が必要なので、今回の依頼条件に従い拡大していない。差分取得・記録は定期化し、内容確認・取込・テスト公開は既存の承認済み手順で行う。

検証：47 Nodeテスト、`python tests/source-refresh-test.py`（全原典失敗時の公開データ不変を含む）、`npm run validate`、`npm run build`。ローカル実取得では町HP差分0、RSS20件、ICS候補20件、公開データのハッシュ不変を確認。GitHubで同じジョブを実行して証拠URLを報告する。将来のcronによる実行実績と手動実行実績を混同しない。

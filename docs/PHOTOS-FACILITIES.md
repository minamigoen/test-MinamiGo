# 飲食店・宿泊施設の実写真（2026-10-14）

運営者の明示許諾を指定の飲食／宿泊2シートだけに適用。本番MinamiGo・元Sheets・共有権限は無変更。美波遺産・パワースポットへ許諾を拡張しません。

## 原因と修正

美波飯のwebApp.gsはA:Lの12列を読み、L列をimageとして返します。index.htmlはそのURLをimg.srcへ直接設定します。テスト版はimage列を除外していたため無表示でした。既存匿名APIの37画像を読み、カード・ピンのポップアップ・詳細へ表示。旧写真なしキャッシュはphotoPolicyで移行し、画像付き正常データを保持します。元画像がなくなれば「写真未登録」、ロード失敗は独自案内イラストへ切替。別施設や素材写真を代用しません。

## 件数・施設同定

- 飲食37施設：37実画像。元APIの町画像30、既存公開Googleusercontent画像7。スマホ390px／PC1440pxで全カード・全施設詳細・全37ピン画像のロードと実寸>0を確認。
- 宿泊27施設：26実画像。座標がない3件も施設詳細で写真を表示。24参考ピンのうち、画像がある23ピンを表示。残る1ピンは写真確認待ちです。
- 当初、元URLだけを読み24件の画像バイト取得に成功していました。しかし追加の施設名照合で、町の画像番号が変わり、シートの14通常画像URLと1サムネイルURLが別施設を指すことを検出しました。ロード成功だけでは正しい施設写真とは判断しません。
- [町公式の宿泊写真一覧](https://www.town.minami.lg.jp/foreign_country/jp/sightseeing.html)の各施設名・個別写真キャプションと照合し、26施設の対応を確認。既存の公開Drive画像4件はファイル名・anyone/reader・匿名取得を確認して優先し、町画像は現在の施設対応へ補正。元Sheetsは修正せず、テストrepoの確認記録だけに保存。
- 清流の郷・B&B m4・かんちゃん亭は元のDriveフォルダ404でしたが、同施設の町公式写真を特定できたため表示を補完。
- **民宿弘陽荘は保留**：元のstay_img6.jpgは現在「えびすロッジ」の写真。弘陽荘に紐づく正しい許諾済み公開画像を特定できないため、「写真の施設対応を確認中」と表示。正しい公開画像URLが必要です。施設自体は一覧／詳細／参考ピンに残します。

写真クレジットは掲載元を表示し、撮影者名を推測しません。Driveフォルダを画像として読み込まず、確認済みfile/d/…/viewを既存Googleusercontentの匿名読取経路へ正規化。未知host・資格情報付きURLは採用しません。外部写真をSWで一括取得・PWA保存しません。写真の許諾と、地点・入口の現況確認は別です。

## 検証・再現

`npm test`、`npm run validate`、`npm run build`。構造／失敗系は既存7ブラウザテスト。`python tests/live-photos.py`は実HTTPS URLで390／1440pxの全施設カードと詳細、全位置付きピンの実画像を1件ずつ確認し、自然寸法と成功件数、画像失敗fallbackをphotos-result.jsonへ記録。CIのlive-test-browser-evidenceに画面とJSONを保存。施設名の対応はdata/stay-review.jsonに原典と確認名を保持し、違う施設名の写真取込は失敗します。

公開テストを開き、既存利用者は「更新して再読み込み」を選択。「食べる」「泊まる」のカードをスクロールし、地図→ピン→詳細→閉じるでポップアップ写真を確認。総88項目、飲食37・宿泊27、美波遺産12・パワースポット12項目、宿泊参考座標24件／保留3件を維持しています。

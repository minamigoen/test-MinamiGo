# 飲食店・宿泊施設の実写真（2026-10-14）

## 許諾と修正原因

サイト運営者が「飲食店と宿泊施設はそもそも写真利用許諾ある」と明示しました。許諾をfood/stayだけに適用し、美波遺産・パワースポットへ拡張しません。元Sheetsの空欄だったライセンス欄は変更せず、テストrepoの許諾記録として保持します。写真の出典と「掲載許諾確認済み」をカード・詳細に表示します。撮影者名を推測して記載しません。

旧版が施設写真を表示しなかった原因は、food-source.jsが公開APIのimage列を意図的に除外し、宿泊も外部リンクだけを保存していたことです。以前の許諾未確認ガードを、今回の明示許諾に合わせて限定解除しました。

本番MinamiGoのwebApp.gsはSheet A:Lの12列を読み、L列をimageとして返します。index.htmlはそのURLをimg.srcへ直接設定し、失敗時はNo Imageに切り替えます。テストも既存の同じ匿名公開API・同じ画像URLを使用し、追加認証・共有権限変更・有料APIはありません。失敗時は自身の案内イラストと文言を使い、別施設や素材写真を表示しません。

## 元データと公開写真

- 飲食37件：匿名公開APIに37件すべてimage URLがあり、Chromeで37/37の実寸>0を確認。町の公開画像30件、既存Googleusercontent画像7件。画像を公開allowlistへ取り込み、背景更新・端末内の正常データ保存にも保持します。
- 宿泊27件：L列の直接画像22件は匿名読込に成功。DriveのフォルダURL5件は画像そのものではないため、そのままimg.srcに設定しません。
- 「海辺の農家民宿クニ舛田」「橋本屋旅館」は既存写真フォルダ内の施設名が一致する画像を確認し、画像ファイルのanyone/readerと匿名取得を確認。既存公開範囲の画像URLへ解決しました。合計24施設に実画像を表示します。
- 「農家民宿 清流の郷」「B＆Bｍ⁴(エムノヨンジョウ)」「かんちゃん亭」の元フォルダは既存Drive接続で404、一覧0件。同名画像検索でも適切な公開画像を特定できませんでした。3件は「元の写真フォルダを取得できません」と区別して表示。元表の画像欄はあるが、利用できる画像URLが未解決です。正しい公開画像ファイルURLが必要です。
- 現在、写真欄自体が空の飲食・宿泊は0件です。今後空になった場合は「写真未登録」と表示し、古い写真や別画像で埋めません。

Google Driveのfile/d/…/viewは既存Googleusercontentの画像読取経路へ正規化。フォルダURL・未知host・資格情報付きURLを写真として採用しません。写真は外部の表示時取得のみで、SWの一括取得やアプリ用保存をしません。

## キャッシュと位置

旧版の写真を除外した10分キャッシュを新許諾版で再利用すると、写真が再び消えるため、photoPolicyを保存して切り替え時に旧キャッシュを再取得します。新APIでimageがなくなった施設は写真を消し「未登録」と表示します。宿泊27件、参考座標24件・保留3件、美波遺産12・パワースポット12項目・合計88項目を維持します。写真の許諾と、地点・入口の現況確認は別です。

## 検証と再現

`npm test`、`npm run validate`、`npm run build`。構造・失敗系：`python tests/photo-policy-browser.py`と既存6ブラウザテスト。公開実画像：`python tests/live-photos.py`。

公開テストを新しいブラウザで開くか、既存利用者は「更新して再読み込み」。食べる37件、泊まる27件でカードをスクロール。実写真は食べる37、泊まる24。地図→ピン→詳細、閉じてポップアップの写真を確認。位置未確定3施設も一覧から写真詳細を開けます。

公開実URLに対し390px/1440pxで全施設を順に表示し、61枚の画像のロード・naturalWidth/naturalHeight>0、カード・ピン・詳細を確認。意図的な画像エラーは案内イラストへ切替。CIのlive-test-browser-evidenceにphotos-result.jsonと画面証拠を保存します。
